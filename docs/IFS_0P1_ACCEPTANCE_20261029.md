状态：实现、回归及真实 WPS/短时 WRF 已通过；21 版已激活，两 API 已经原维护入口安全加载，共享组件 2.2.7 已在正式页面复验。

## 产品与兼容性

| 选择 | 请求标识 | 独立资料根目录（稳定别名下） | 完整周期 |
| --- | --- | --- | --- |
| GFS 0.25° | `gfs` | `WRF_WORKBENCH/forcing/gfs` | 73 个小时 |
| ECMWF IFS 0.25° | `ecmwf`（兼容 `ec`） | `WRF_WORKBENCH/forcing/ecmwf` | 25 个时次 |
| ECMWF IFS 0.1° | `ecmwf_0p1` | `WRF_WORKBENCH/forcing/ecmwf_0p1` | 25 个时次，每时次 SFC + PL |

旧标识、路径、文件名、分片、引用和任务记录不迁移。新目录可用 `WRF_HPC_EC_0P1_DIR` 配置，但拒绝与旧目录重叠、相对跳转及读取其他产品的队列/历史。任务编号、校验、受管启动、静态访问、删除和智能体冻结/查询合同兼容新标识；不修改旧冻结计划。

三个产品共用原 00Z、f000–f072、最近两周期的预取和保护策略；ECMWF 两种分辨率均为 3 小时间隔。继续由真实 f072 探测确认发布，0.1° 必须同时探测 SFC 和 PL，不能从 0.25° 就绪推断 0.1° 已发布。默认资料源仍为 GFS，旧 IFS 选项仍为 0.25°，不自动升级用户选择。

0.1° 的队列、工作器与继承传输锁、周期锁、分片、下载历史和清理目录均绑定新根目录。每时次先完成两个独立续传组件，再 fsync、原子合并为 `ecmwf.t00z.ifs.0p1.fNNN.grib2`；提交记录绑定两个组件及结果文件 device/inode/size/mtime。单独 SFC、未提交的合并结果及已变更结果不算就绪。合并后仅移除本次已提交的冗余完整组件，未完成分片和逐次历史保留。历史位于周期外，周期清理不会带走失败原因。

任务开始前沿原语义校验再检查真实 0.1° 网格、共同气压层、四层土壤温湿度、空间和时间覆盖。原运行身份、引用保护、隔离后后台清理和未知事务不重放规则保持。无新数据库表；旧保留周期 JSON 只读补出空的新产品键，不改版本或旧保留列表。旧客户端的两键策略请求仍兼容。

这是有限三小时算例与格式兼容性验收，不证明全周期吞吐、所有地形/物理组合或预报精度提升。公开下载存在 TLS/连接提前关闭和低速问题，保留分片及原因，不把等待发布或连接失败显示为已就绪。
